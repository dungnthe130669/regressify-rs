# Snapshot Frontend

Verified: 2026-10-13

- Suite `displayName` is optional in version-2 summaries/reports. `suiteLabel`
  supplies all visible suite labels while IDs remain route/asset keys. The
  `suite display names` browser test covers desktop/mobile search, titles, Info,
  markup-like text, and stable deep links. Wait for loaded overview rows before
  reading the title; Vite initially serves the HTML title placeholder.
- The [SPA](../../frontend/README.md) uses root-based clean URLs and lazy suite JSON.
  `bun run build` replaces `src/snapshot/data` and generates the Rust include list;
  Cargo does not execute JavaScript tools. All runtime assets, fonts, JSON, and
  image URLs use stable filenames plus `?v=`; only HTML revalidates. Versions use
  [get_asset_version](../../src/snapshot/helpers.rs) with 20 characters. Frontend
  [versioning](../../frontend/scripts/version-assets.ts) mirrors SHA-384/base64url;
  Rust tests verify the built references. CDN keys must include the query parameter.
- [Git attributes](../../.gitattributes) preserve generated bytes with `-text`.
  Windows CRLF checkout conversion caused the recurring Rust resource-version
  failure: converting the JavaScript back to LF reproduced the HTML's version.
  Rebuild already converted assets with `bun run --cwd frontend build`; rebuilding
  without preserving bytes in Git only repairs the current checkout temporarily.
  The [asset-sync regression](../../frontend/scripts/sync-assets.test.ts) checks
  LF and CRLF inputs with autocrlf enabled; the Rust test passes in release mode.
- That Git regression uses `GIT_CONFIG_GLOBAL=NUL` on Windows. Node's `os.devNull`
  device path is rejected by Git for configuration reads.
- [Schema](../../frontend/src/data/report.ts) and [Rust types](../../src/snapshot/site.rs) use version 2; raw HTML/images are omitted, page links are HTTP(S)-only, and report JS is parsed as JSON, never run.
- [Conversion](../../src/snapshot/capture_report.rs) reserves `error` for capture failures; optional `comparisonError` preserves legacy dimension/missing-reference/comparison diagnostics.
  Converter tests and `visual mismatches remain failed` browser checks cover placeholders, counts, filters, and Info labels.
- Scenario and generated capture display names come from the shared Rust resolver,
  not frontend string manipulation; see [results naming](desktop-results.md).
  The search/navigation fixture includes colliding URL paths and repeated viewports.
- [Synthetic fixtures](../../frontend/scripts/create-fixture.ts) use local Chromium,
  not production sites. Biome must exclude `.fixtures`: formatting `config.js`
  removes JSON key quotes and intentionally fails Rust's strict report parser.
- Biome 2.5 uses `rules.preset: recommended`. Verify the migrated value; a migration
  can select `none`, making a nominally clean run stop checking source rules.
- Windows editor watchers can prevent renaming `src/snapshot/data`. The sync script
  stages the build, atomically replaces individual files, and removes stale files
  afterward; its tests assert the destination directory identity remains unchanged.
- Snapshot generation validates all suites in a temporary directory before
  replacing stable paths; an invalid later suite preserves the old report. Repeated
  generation changes image/suite/manifest versions without file-list churn and
  removes obsolete files only inside generated `_snapshot` directories.
- [Snapshot I/O](../../src/snapshot/site.rs) stages inside the report output root,
  not the OS temp directory, and errors retain their operation, path, and OS cause.
  The `snapshot_io_errors_` tests cover discovery/staging and Windows sharing locks;
  [worker stderr](../../tests/desktop_worker.rs) preserves the exact path. Lock tests
  assert error 32, not access-denied error 5. A read-only attribute alone did not
  block legacy cleanup on the tested Windows runtime.
- Removal of confirmed-empty generated directories is best-effort after publishing:
  deletion errors warn and retain the directory; already-removed paths are ignored.
  Directory reads, stale-file deletion, artifact I/O, and symlink checks remain fatal.
  `snapshot_cleanup_keeps_blocked_empty_directories_without_failing` and the worker's
  `snapshot_worker_warns_for_blocked_empty_directory` cover Windows directory locks,
  unchanged capture/inventory data, warning output, and later cleanup.
- Editor symbol rename may skip desktop-gated references when rust-analyzer uses
  default features. Always run the desktop-feature check after a shared rename.
- [Review navigation](../../frontend/src/components/ReviewNavigation.tsx) loads only
  the selected suite's scenarios. The current suite is a searchable Floating UI
  dropdown, not a disclosure; its overlay scrolls without moving the scenario pane.
  `review navigation` tests cover keyboard/pointer selection, dismissal, search reset,
  long labels, viewport bounds, and accessibility on desktop/mobile.
  Portal into the enclosing native mobile dialog, using the default root on desktop.
  Escape capture and default prevention keep dismissal out of the native drawer.
  List-navigation orientation does not belong on the outer searchable dialog.
  [Shell](../../frontend/src/App.tsx) owns separate
  left/right scroll areas and pointer-captured divider resizing; preferred desktop
  width survives narrow/mobile viewports. Tailwind resets native `hr` height to zero,
  so the vertical divider explicitly needs `height: 100%`.
- [Overview](../../frontend/src/pages/OverviewPage.tsx) sorts all five columns,
  using raw counts/ratios instead of formatted percentages. `overview sorts every
  column` covers direction changes, filter preservation, and refresh. Fully passing
  nonempty suites highlight passed counts green; failures highlight failed counts
  red but use neutral bar fills. `pass-rate bars distinguish` checks actual PNG
  pixels in both themes, including empty bars and rounded 100% failures. Phones
  retain every column in a horizontally scrollable table. Mocked suite IDs must
  be explicit: search includes IDs, and Vite/production manifest orders differ.
- [Shell](../../frontend/src/App.tsx) uses growing flex columns and review panes
  below the actual compact header height. It stacks report heading/subheading;
  the overview page heading is `Snapshot Overview`.
  `bun run test:e2e --grep footer` covers short/filtered/missing pages and long
  document/review scrolling on desktop and mobile.
- [Image viewer](../../frontend/src/components/ComparisonViewer.tsx) reserves full height in the right page; only explicit zoom controls change scale, not native scrolling.
  Optional `imageSizes` provides pre-load sizing; `dimensions` holds deltas. Legacy reports discover sizes on load.
  Delayed-load tests emulate reduced motion to exclude the page entrance animation.
- Side-by-side crosshairs share image-pixel coordinates, excluding unavailable or
  out-of-bounds pixels. Their inverse-scaled overlays keep strokes one screen pixel
  wide. The `side by side crosshairs|scrolling over images` browser checks cover
  alignment and cleanup on desktop/mobile. Image nodes have `pointer-events: none`;
  hover their wrappers to wait for stable layout before reading image bounds.
- [Info dialog](../../frontend/src/components/CaptureInfo.tsx) uses Floating UI, native selection/copy, dialog semantics, and a non-banner heading.
  Pinning ignores `hover` and `safe-polygon` close reasons; focus uses `visibleOnly: false`.
  `shift({ crossAxis: true })` retains full viewport visibility; the Info test moves the pointer to an uncovered corner to check pinning on phones.
- [Image review](../../frontend/src/pages/ImagePage.tsx) preserves `suiteView=list` during `view=log`; suite-list tests cover switching, refresh, and Results navigation.
- Suite failure arrows navigate only filtered failed cards, retain the suite URL,
  focus/highlight the target, and disable at endpoints or when no failures remain.
- [Shell](../../frontend/src/App.tsx) uses the shared [desktop SVG](../../assets/icon.svg)
  for the logo/favicon; [Vite](../../frontend/vite.config.ts) supplies its content
  version at build time. Suite/image titles prepend the route's decoded suite name;
  the overview restores the report title.
- [Suite previews](../../src/snapshot/capture_report.rs) are fast deterministic PNGs:
  full-image previews at most 640x480, top-cropped grid thumbnails at most 640x400.
  [ReportImage](../../frontend/src/components/ui.tsx) bounds active sources; review uses originals.
- [Theme startup](../../frontend/index.html) applies saved/system appearance before React.
  [ThemeControl](../../frontend/src/App.tsx) stays mounted in Settings > Appearance,
  persisting explicit choices and handling cross-tab/OS changes while closed.
  `--grep 'report header|settings popup|theme'` tests spacing, dialog growth/focus,
  first-paint styling, and unavailable storage on desktop/mobile.
- Browser image-failure tests intercept the exact URL returned in suite data.
  Development fixtures share preview images instead of using production's
  per-suite image directories; assuming those directories misses the request.
- `bun run test:e2e` tests Vite by default. Set `SNAPSHOT_URL` to the local
  `bun run preview` address to exercise the Rust-generated fixture and hosting headers.
  Source and production browser checks passed on desktop and mobile.
- [Asset workflow](../../.github/workflows/snapshot-assets.yml) builds release source
  read-only, transfers generated assets to a separate master checkout, and opens
  a generated-only PR using `gh`. Updates/deletions use observed-SHA Git leases;
  no-change runs close stale PRs without committing. Offline checks mock both
  commands and feed Bash UTF-8 bytes to avoid Windows stdin newline conversion:
  `python ci/test-release.py -k snapshot_frontend`.
